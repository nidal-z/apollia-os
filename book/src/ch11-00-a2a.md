# Agents qui collaborent : A2A

Jusqu'ici, chaque agent du livre travaille seul. Il reçoit une tâche, exécute, retourne un résultat. C'est suffisant pour la plupart des tâches PME.

Mais certains workflows dépassent les capacités d'un seul agent. Analyser un rapport financier, générer un devis et l'envoyer par email — trois domaines distincts, trois Workers spécialisés. Sans mécanisme de collaboration, vous êtes obligé d'orchestrer manuellement depuis votre code applicatif, en enchaînant les appels à chaque agent un par un.

**A2A (Agent-to-Agent)** est la réponse d'Apollia OS à ce problème. Il permet à un agent de **déléguer** une sous-tâche à un autre agent spécialisé, d'attendre son résultat, et de continuer — comme un appel de fonction, mais entre agents autonomes.

---

## Deux rôles : Director et Worker

Dans une composition A2A, les agents jouent deux rôles distincts :

**Director Agent** — orchestre le workflow, délègue les sous-tâches aux Workers. Il connaît les skills disponibles et décide quand les invoquer.

**Worker Agent** — spécialiste d'un domaine. Il expose des `skills` invocables par d'autres agents. Il ne sait pas qui l'appelle.

Ces rôles ne sont pas exclusifs : un agent peut être Director pour certaines tâches et Worker pour d'autres.

---

## Deux modèles d'interaction

### Délégation explicite — `ctx.delegate`

Le Director appelle un Worker par son `skill_id`, attend le résultat, et continue :

```python
# Director Agent — délégation explicite
result = await ctx.delegate(
    "analyze-csv",
    {"input": {"text": "Analyse /data/ventes.csv"}},
    timeout_secs=120,
)
```

Simple, lisible, déterministe. Vous savez exactement quel Worker est appelé à quel moment.

### Outils A2A dans ORIA — `a2a:<skill_id>`

Avec l'`A2AToolsProvider`, les Workers deviennent des outils virtuels dans la boucle ReAct du Director. Le LLM voit `a2a:analyze-csv` dans sa liste d'outils et peut l'appeler comme n'importe quel outil natif — sans que le code du Director change :

```python
# Le LLM du Director Agent choisit seul d'appeler ce Worker
ctx.tools.call("a2a:analyze-csv", {"text": "Analyse /data/ventes.csv"})
```

Plus autonome, mais moins prévisible. Adapté aux Directors qui doivent décider dynamiquement de quels Workers utiliser en fonction du contexte.

## Vue d'ensemble de l'écosystème A2A

```
Director Agent
  │
  ├── ctx.delegate("analyze-csv", payload)
  │         │
  │         ▼
  │   SkillIndex.resolve("analyze-csv")
  │         │
  │         ▼
  │   csv-data-worker [Active]
  │         │ AIPTask
  │         ▼
  │   Worker exécute → résultat
  │
  ├── ctx.delegate("read-pdf", payload)
  │         │
  │         ▼
  │   pdf-worker [Active] → résultat
  │
  └── Résultat final consolidé
```

Le runtime résout les `skill_id` via un index inversé (`SkillIndex`) maintenu dans l'`AgentRegistry`. La résolution est instantanée — pas de découverte réseau, pas d'appel externe.

---

## Alignement avec les standards

Apollia OS s'aligne sur le protocole A2A de Google (2025) sans en dépendre. Les structures de données (`TaskState`, `AgentCard`, `skills`) correspondent aux spécifications A2A. Si un agent déclare `supports_a2a: True`, son `AgentCard` est automatiquement exposée à `/.well-known/agent.json` — compatible avec tout client A2A externe.

La philosophie : être **compatible par construction**, pas par implémentation complète.
