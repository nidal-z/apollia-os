# Apollia OS - Context for AI Agents

> This file is intended for AI coding agents (Claude Code, Cursor, Copilot, etc.) working on the
> Apollia OS codebase. It provides a dense, accurate description of the project so that context
> windows are used efficiently and agents make fewer wrong assumptions.

---

## What is Apollia OS?

Apollia OS is an **open-source Rust runtime for executing autonomous AI agents locally and
sovereignly**. It bridges any Python agent (LangGraph, CrewAI, custom) with a production-grade
runtime that handles tool execution, memory, permissions, LLM routing, pipelines, HITL approval,
and observability - without any cloud dependency.

The key differentiator is **ReAct autonomous agents** (not deterministic LLM pipelines): agents
observe → reason → act in a loop bounded by a StepBudget, with the runtime enforcing guardrails.

**Author:** Nidal (CTO & Co-founder Apollia), solo development, evenings/weekends.
**Language distribution:** ~70% Rust, ~20% Svelte/TypeScript, ~10% Python (SDK + agents).
**Current phase:** Beta preparation - fact-checking sprint validating API contracts.

## Core Architecture

### The Actor Model

The runtime uses a strict **Tokio actor pattern**:
- Each subsystem is a separate actor with its own `mpsc::channel`
- No `Arc<Mutex<T>>` shared across actors - everything goes through message passing
- The `Supervisor` starts actors in order and monitors them

**Actor startup order:**
1. EventBus → 2. AgentRegistry → 3. ToolRegistry → 4. MemoryEngine → 5. LlmRouter →
6. TriggerEngine → 7. TaskRouter → 8. ORIAEngine → 9. APIServer

### The ORIA Loop

Every agent task runs through the ORIA (Observer-Reasoner-Actor) loop:

```
Observe  → gather context (memory, tools, previous steps)
Reason   → LLM call produces a plan or next action
Act      → execute tool calls, emit events
Iterate  → until StepBudget exhausted, task done, or HITL pause
```

Two execution modes (ADR-004):
- **Direct** (atomic): agent handles its own ReAct loop in `run()`
- **Orchestrated**: ORIA generates a multi-step plan; agent is declarative

### The Python Bridge (AIP)

Python agents are loaded via PyO3. The bridge exposes `RuntimeContext` to agent code:

```python
async def run(self, task: AIPTask, ctx: RuntimeContext) -> AIPResult:
    await ctx.tools.call("file_read", {"path": "/data/report.txt"})
    await ctx.memory.remember("finding", "...")
    result = await ctx.llm.complete("Summarize: ...")
    return AIPResult(output="done")
```

Key `RuntimeContext` fields (from `sdk/apollia/stubs/context.py`):
- `ctx.tools` → ToolsProxy (call, list, tool_call_count)
- `ctx.memory` → MemoryProxy (remember, recall, recall_procedure, learn_procedure)
- `ctx.llm` → LlmProxy (complete, with_model)
- `ctx.log` → Logger (info, warning, error)
- `ctx.step_budget` → StepBudgetView (max_steps, max_tool_calls, wall_clock_secs, steps_remaining)
- `ctx.task_id`, `ctx.agent_id`, `ctx.project_id`

**Important:** `ctx.step_budget.tool_calls_remaining` is currently hardcoded to `-1` (stub).
Use `ctx.tools.tool_call_count()` for actual count.

### StepBudget

Defined in `crates/apollia-core/src/budget.rs`:

```toml
[step_budget]
max_steps = 30           # default
max_tool_calls = 60      # default
wall_clock_secs = 600    # default (NOT wall_clock_timeout_secs)
```

The runtime enforces this budget - it cannot be bypassed by agent code.

### Agent Contract (AIP - Agent Interface Protocol)

Minimal duck-typing contract (ADR-003):

```python
def manifest() -> dict:
    return {
        "id": "my-agent",
        "name": "My Agent",
        "version": "0.1.0",
        "description": "...",
        "step_budget": {"max_steps": 20, "max_tool_calls": 40, "wall_clock_secs": 300},
        "tools_required": ["file_read", "web_search"],
    }

async def run(task: AIPTask, ctx: RuntimeContext) -> AIPResult:
    ...
```

No base class required. `manifest()` + `async run()` are the only contract.

## Key Technical Conventions

### Rust

- **Errors:** `thiserror` everywhere - `anyhow` is FORBIDDEN in workspace crates
- **Unwrap:** zero `unwrap()` in production code - only in `#[cfg(test)]`
- **Actors:** `mpsc::channel` + clonable handle - never `Arc<Mutex<T>>` cross-actor
- **Logging:** `tracing::info!(field = %val, "event")` - no format strings in log macros
- **Docs:** `///` on every public struct, enum, fn

### Python SDK

- Stubs live in `sdk/apollia/stubs/` - these are the source of truth for Python API
- `AIPTask` fields: `task_id`, `agent_id`, `input`, `project_id`, `message_id`, `timeout_seconds`
- `AIPResult` fields: `output`, `success`, `error`, `metadata`, `step_count`, `tool_calls`
- `recall_procedure()` returns `list[dict]` with keys `trigger`, `steps`, `created_at` - never `None`

### Git Commits

Conventional commits required:
```
feat(apollia-core): add AgentManifest type
fix(apollia-tools): handle missing tool gracefully
docs(wiki): update StepBudget reference
```
Scope = crate name or `wiki`/`book`/`cli`. One commit = one logical task.

### Testing

- `#[tokio::test]` for all async tests
- GIVEN / WHEN / THEN comment structure
- `cargo test -p apollia-XXX` must pass before committing to that crate

## Memory System

Three layers (all in SQLite FTS5):
- **Episodic:** timestamped events from agent runs
- **Semantic:** searchable knowledge fragments
- **Procedural:** `learn_procedure(trigger, steps)` / `recall_procedure(trigger)`

Memory is **always at agent initiative** (ADR-007) - the runtime never auto-injects.
Namespace convention: `{project_id}:{manifest_namespace}` (ADR-056).

---

## Permission Model

Three scope layers (ADR-061, ADR-082), stored in `~/.apollia/governance.db`:

| Scope | Storage | Lifetime |
|---|---|---|
| Session | In-memory | Until runtime stops |
| Project | `governance.db` | Persistent, project-bound |
| Global | `governance.db` | Persistent, all projects |

HITL approval prompts pause task execution and emit a `TaskPaused` event. The desktop app
shows an approval card; CLI uses `apollia task resume <id> --approve|--reject`.

## CLI Reference

Pattern: `apollia-os <noun> <verb>` (ADR-008)

```
apollia-os start                    # boot runtime
apollia-os status                   # overview: agents, tools, health
apollia-os run <agent> "<task>"     # submit task (--wait, --stream, --detach)
apollia-os agent list|start|stop|info|logs|validate|new
apollia-os task list|status|result|cancel|retry|resume|inspect
apollia-os memory inspect|list|clear|purge|learn-procedure|export|import
apollia-os tools list|enable|disable|config|reload|credentials|describe
apollia-os permissions list|revoke|audit
apollia-os pipeline list|run|runs|status
apollia-os trigger list|status
```

Exit codes: 0 success · 1 input error · 2 runtime error · 3 task failed · 4 timeout (⚠️ not yet implemented) · 5 SIGINT

Global flags: `--json` · `--socket PATH` · `-q/--quiet` · `-v/--verbose` · `--debug` · `--no-color`
